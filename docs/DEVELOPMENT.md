# Development Guide

## Environment Setup

```bash
git clone https://github.com/sanchez314c/dark-sticky-notes.git
cd dark-sticky-notes
npm install
npm start
```

That's all that's needed. No build tools, no TypeScript compile step, no hot reload server.

## Project Structure

```
dark-sticky-notes/
├── main.js           Main Electron process
├── preload.js        Context bridge (IPC security layer)
├── renderer.js       Renderer process UI logic
├── note.html         Note window template (CSS inline in <style>)
├── package.json      Project config + electron-builder packaging
├── resources/        Icon assets (icon.icns, icon.ico, PNGs, icons/ for Linux)
├── scripts/          Shell scripts for run/build tasks
├── docs/             Developer documentation
└── archive/          Displaced/deprecated files (do not delete)
```

## Development Workflow

Since there is no transpile/bundle step, the loop is:

1. Edit a source file
2. For renderer changes (`renderer.js`, `note.html`): press Cmd+R/Ctrl+R in the note window to reload the renderer
3. For main process changes (`main.js`, `preload.js`): quit and restart with `npm start`

The quickest iteration for renderer changes uses the Dev Tools (Alt+Cmd+I / Alt+Ctrl+I) — you can inspect elements, test CSS live, and console.log in the renderer.

## Code Style

Enforced by `.editorconfig`:
- 2-space indentation for `.js`, `.html`, `.css`, `.json`
- 4-space indentation for `.py`
- LF line endings
- UTF-8 encoding
- Final newline required

No linter is configured. Follow the patterns in the existing code — vanilla ES2018+ JS, no classes, function declarations for named functions, arrow functions for callbacks.

## Making Changes to the IPC API

Any new feature that crosses the main/renderer boundary requires changes to 3 files:

1. **`main.js`**: Add `ipcMain.handle('channel-name', handler)`
2. **`preload.js`**: Add method to `contextBridge.exposeInMainWorld('electronAPI', { ... })`
3. **`renderer.js`**: Call `window.electronAPI.methodName()`

The preload script is the security boundary. Never put logic in preload.js — it should only be thin wrappers around `ipcRenderer.invoke` and `ipcRenderer.on`.

## Data Persistence

The custom `store` object in `main.js` (lines 11-35) handles all persistence. It reads and writes `notes.json` synchronously using `fs.readFileSync` / `fs.writeFileSync`. This is intentional — note saves are infrequent and synchronous writes prevent partial-write data loss on force-quit.

The `notes` object key is always the UUID v4 string generated by `uuidv4()` from the `uuid` package.

## Testing

There is no automated test suite. Manual test checklist before any commit:

- [ ] `npm start` — app launches, default note appears
- [ ] Create note (➕ or Cmd+N) — second note created, offset position
- [ ] Type in both notes, wait 1+ second — content saves (quit + reopen to verify)
- [ ] Move and resize notes — positions restore after restart
- [ ] Color picker — all 7 colors apply and persist
- [ ] Pin (📌) — window stays on top of other windows
- [ ] Minimize (➖) — window minimizes to taskbar
- [ ] Close (✕) — note closes and is removed from storage
- [ ] Cmd+W — closes current note
- [ ] Cmd+Q / quit — all notes restore on next launch

## Icon Generation Scripts

If you need to regenerate icons from a source image:

```bash
# Create base icon from scratch (requires PIL/Pillow)
python3 scripts/create_icon.py

# Convert to all required formats
python3 scripts/convert_icons.py
```

Output goes to `resources/`.

## CI

GitHub Actions runs on every push to `main`/`master` and on pull requests. The workflow is `.github/workflows/ci.yml` — it runs `npm ci` and `npm test` on Ubuntu with Node.js 20. Since there are no tests yet, `npm test` exits with code 1 but the workflow still validates that `npm ci` succeeds cleanly.
